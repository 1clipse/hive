# 协作提示与按需指南改进

用户已授权实施。基线 `b111938`，独立工作树 `hive-collaboration-guidance`；原共享目录的修改不纳入本次工作。

## 目标

让主控围绕用户目标、验收证据、时间与资源成本选择分工；让成员在当前事件拿到适用的指引。沿用 2026-09-05 协作 spec 的责任、权限、输入水位和用户资源授权边界。

## 实施顺序与归属

1. 角色传递：workflow 自定义模板的 description 穿透到成员和启动提示；核对自定义 CLI 的启动能力边界。
2. 共同原则：直接执行与委派的选择、事实询问与决策升级、静默任务进度、按条件读取指南；收敛内置角色的重复说明，删除以空轮次或多数票代替验收的示例。
3. 事件提示：普通 question 与恢复复用正确回复路由；回答历史问题不重开责任；收据 ack 与问题 answer 分开。
4. 指南入口：内部 CLI 使用已认证工作区的实时指南；离线帮助明确能力未知。外部主控增加绑定内只读 guide action，使详细命令说明可按需读取。
5. 定向验证、四路独立 review、整理结果和可审查提交。

## 验收与边界

- 自定义角色描述在真实创建/启动路径保留。
- `team guide` 在子目录或其他目录中仍匹配已认证工作区；错误身份拒绝；配置变化立即反映，无静默离线回退。
- 外部 guide 保留既有宿主身份与绑定认证；读取不创建操作记录、不消费报告、不变更任务。
- 生成的普通/历史问题回复命令能通过真实协议执行；责任和 pending 数保持原义。
- 本阶段不增改 `tests/`，使用现有定向集成与小型可运行 self-check；跑 `pnpm check` 和 `pnpm build`。不以字符串存在证明模型服从。
- 不改数据库 schema、投递状态机、三态成员模型、自动扩编策略或任意 CLI 的交互能力；不重启用户 runtime、不合并或发版。
- 仓库开发的四路里程碑审查继续遵守；不把这项开发规则注入用户的任务流程。
- 真实模型效率比较单独记录，未取得可比结果时不宣称提速或节省费用。
