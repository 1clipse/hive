# 协作改造实施与验收

设计：[面向工作的协作](../specs/2026-09-05-task-collaboration.md)。完整目标由设计定义，以下勾选只表示实现工作，不代替产品验收。

## 实施责任

- 后端：关联派单、schema migration、消息授权、消息级 outbox、报告水位、取消和重启投递。
- CLI/HTTP/MCP：related-to、message/messages、显式 seen、严格参数、snake_case 和认证；外部控制器宿主身份、operation_id 幂等及收据流。
- 上下文：启动/派单/状态/报告/恢复提示一致，短锚与按需指南，保留自定义角色。
- 恢复与 UI：账本恢复、历史消息、已有 Action Center 问题与投递展示，真实事件通知。
- 集成：角色/配置资源发现、设计同步、断言式真实链路检查、独立审查和最终审计。

并行修改有明确文件所有权；共享边界先统一接口。原共享工作树不修改。已在独立分支合入 `origin/main 950f04a`（整合提交 `ef49556`，包含 #58 外部控制器）；这不代表本分支已合并到远端 main。未发布，不创建外部评论或部署。

## 顺序

1. 记录用户原则、关键接口和状态边界；GPT-6 Astra max 独立挑战关键竞态与历史答疑。
2. migration + stores + 操作事务，与 CLI/路由、提示重构并行。
3. 接通恢复、启动后投递、既有 UI 展示和资源发现。
4. 跑独立 self-check，修复真实失败；静态检查、build 和因 migration 要求的全量旧测试。
5. 跑真实 CLI 场景核对结果与交互负担；浏览器查看现有 UI（浏览器不代替手机验收）。
6. 四维独立审查，逐项解决严重问题，按目标逐项审计；只在证据充分时完成目标。

## 协议验证矩阵

使用真实 HTTP、SQLite、PTY 和 CLI，无 fetch/PTY mock；临时目录隔离并可靠清理。

| 场景 | 必须证明 |
|---|---|
| 普通工作 | 一个已配置成员完成真实产物，CLI/model未被替换，无新增成员 |
| 提问和补充 | 同一责任保持 open，pending不增长，回答关联正确，新要求进入最终产物 |
| 审查返工 | 独立审查责任关联；已report作者可受限答疑；修复新关联责任，旧报告不重开 |
| 真并行 | 两项独立责任不互相结算；明确文件归属，整合结果正确 |
| 提交竞争 | 补充先则拒绝旧seen，report先则拒绝新要求；无固定sleep模拟竞争 |
| 水位 | 自发消息/progress/他人聊天不阻止报告；不自动填seen；失败报告也需诚实确认输入 |
| 权限 | 跨workspace、非参与者、错误source、伪造token、无reply_to历史发言、cancelled消息均拒绝 |
| 恢复 | 乱序报告和取消后的开放责任准确；未投递消息可恢复；重复不增派单 |
| 取消/停止 | 停止不自动启动；取消保留历史但停止未开始投递；不声称所有进程已停 |
| 兼容 | 旧CLI无新输入可report，有输入明确拒绝；旧status不静默丢阻塞 |
| 外部控制器 | 宿主thread绑定认证；message/messages与内部同契约；operation_id同输入回放、异输入/未确认操作拒绝；read_reports/ack与answer/seen各司其职 |
| 控制器换绑 | queued历史Q断连事务退役，inflight阻止断连；旧thread不可回答给新绑定；同thread重绑不能复活退役Q |
| 数据升级 | 官方41控制器不被占用；42消息和43精确默认模板刷新；自定义角色与既有数据保留 |
| 提示 | 用户角色保留；每条消息不附长角色/动作菜单；恢复后可重新查询工具与任务 |

临时测试纪律未恢复：不新增/修改 `tests/`，使用独立断言式 `scripts/check-team-collaboration.ts`，同时运行已有核心集成。若旧测试断言已被用户批准的新语义替代，逐条列出证据，不为旧预期扭曲产品。migration触发全量执行要求，失败必须报告并分析，不能冒称全绿。
