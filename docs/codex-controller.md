# 用 Codex App 指挥 Hive 团队

第一期面向同机、同一用户的 macOS 环境。Codex App 保持运行，Hive 管理成员 CLI 和任务记录。外部模式没有第二个内部主控模型。

## 一次性连接

安装支持外部主控的 Hive 构建后，执行：

```sh
codex mcp add hive-controller -- hive mcp --controller
```

在 Codex App 重新加载 MCP 配置或重新打开会话，使新工具可用。Hive 与 Codex CLI 应使用同一用户的环境和会话存储。本机需有支持 `queue` 子命令的 Codex CLI；已验证版本为 0.153.4。

`hive mcp --controller` 提供直接成员管理；原 `hive mcp` 保留 Supervisor goal 接口，二者不要混用。面板中的接入命令会带上 Runtime 的实际端口；手动配置自定义端口时，在命令后添加 `--base-url http://127.0.0.1:端口`。

## 创建团队

1. 在 Hive 新建工作区，选择「Codex App」外部主控模式。
2. 复制面板中的连接指令，在项目对应的 App 会话发送。无需手填会话 ID。
3. App 调用连接工具后，在 Mac 本机的 Hive 面板核对目标会话并确认。手机远程面板会提示返回 Mac 完成绑定。
4. 在 Hive 添加成员，选择成员自己的 CLI；或在 App 明确要求创建成员。
5. App 首次连接后先调用 `inspect` 核对工作区路径，再读取该目录中的任务和产物。在 App 中提出任务。成员通过 `team report` 汇报，Runtime 通知 App，主控读取结果后继续调度。

工作区只能绑定一个主控会话。有未完成任务或未接收结果时，不能换绑。外部模式下成员的 idle/working/stopped 仍只描述成员自身，不用来推断 App 在线状态。

## 如何理解汇报状态

任务已汇报：Hive 已保存成员结果。通知已入队：Codex CLI 已接受后续消息。结果已接收：主控已读取并确认接收。以上均不代表主控认可或验收了工作。

通知失败不会撤销已经完成的任务。面板会提供「复制读取汇报请求」，将它发送到绑定的 App 会话即可读取已保存的结果。超时可能发生在实际入队之后，因此重试可能产生重复提醒；主控应读取已有事件，不重新执行原任务。普通进展保留在任务记录中，不逐条唤醒模型。

## 当前边界

已验证空闲但已加载的 App 会话可以被普通进程唤醒。App 完全退出、目标归档/未加载、不同机器和其他客户端不在第一期唤醒承诺内。若提示未收到通知，应先打开绑定会话并读取 Hive 结果，不能据此判定成员没有完成工作。

同用户本机的进程属于当前信任范围。会话 ID 是投递地址，不是密码；MCP 从宿主调用元数据读取身份，Hive 根据显式确认的绑定检查写操作，不宣称隔离同用户恶意进程。
